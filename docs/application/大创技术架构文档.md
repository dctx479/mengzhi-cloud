## 1. 项目概述

蒙智云AI赋能云平台是一个面向内蒙古特色农产品营销场景的SaaS级智能平台，深度融合大语言模型（LLM）、知识图谱（KG）、检索增强生成（RAG）、多模态内容生成与多平台分发等AI技术，为政府、企业和农户提供从内容创作、智能客服、品牌IP孵化到效果监测的一体化AI营销解决方案。

### 1.1 核心业务场景

| 场景 | AI能力 | 业务价值 |
|------|-------|---------|
| **产品营销内容生成** | LLM + Few-Shot Prompt | 1分钟生成多平台文案，效率提升10x |
| **智能客服7×24h** | RAG + Function Calling | 工单自动解决率≥70% |
| **直播话术实时生成** | 流式LLM + 上下文融合 | 直播间互动转化率提升25% |
| **品牌IP智能体** | Agent + 长期记忆 | 0成本打造数字员工 |
| **多平台一键分发** | 适配器模式 + 异步编排 | 一次创作，4平台同步 |
| **效果监测分析** | 事件流 + 实时聚合 | 数据驱动营销决策 |
| **文化知识图谱** | 隐式KG + 路径推理 | 农产品文化故事挖掘 |

### 1.2 技术栈总览

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **前端** | Vue 3 + TypeScript + Element Plus + Vite | 组件化、类型安全 |
| **后端** | FastAPI + SQLAlchemy 2.x + Pydantic v2 | 异步、高性能、自动文档 |
| **AI框架** | LangChain + 自研Agent | 灵活扩展、国产模型友好 |
| **LLM** | 通义千问 / DeepSeek / OpenAI兼容接口 | 多模型路由、国产化优先 |
| **数据库** | PostgreSQL（主）+ Redis（缓存/队列）+ Elasticsearch（搜索）| 关系+缓存+全文检索 |
| **多租户** | Schema-per-Tenant 隔离 | 企业级数据隔离 |
| **部署** | Docker + Nginx + Systemd | 轻量级私有化部署 |
| **监控** | Prometheus + Grafana + Sentry | 全链路可观测 |

## 3. 核心算法与AI能力

### 3.1 大语言模型路由策略

平台采用**多模型动态路由**架构，根据任务类型、成本、延迟自动选择最合适的LLM。

```mermaid
graph TD
    REQ[LLM 请求] --> CLASSIFY{任务分类}
    CLASSIFY -->|简单对话/客服| FAST[快速通道<br/>DeepSeek-V3 / Qwen-Turbo]
    CLASSIFY -->|复杂创作/分析| POWER[强力通道<br/>Qwen-Plus / Qwen-Max]
    CLASSIFY -->|代码/技术| CODE[代码通道<br/>DeepSeek-Coder]
    FAST --> CACHE{Redis 缓存?}
    CACHE -->|命中| RETURN[直接返回]
    CACHE -->|未命中| CALL[调用 LLM API]
    POWER --> CALL
    CODE --> CALL
    CALL --> STREAM[流式输出 SSE]
    STREAM --> LOG[记录到审计日志]
    LOG --> RETURN
```

**核心设计要点**：
- **缓存复用**: 高频问答场景使用Redis缓存，命中率可达40%+
- **流式响应**: Server-Sent Events（SSE）协议，首token延迟<500ms
- **降级熔断**: 单一模型故障时自动切换备用模型

### 3.2 检索增强生成 (RAG) 流程

智能客服模块基于RAG架构，融合企业知识库与文化元素知识图谱。

```mermaid
sequenceDiagram
    participant U as 用户
    participant API as Chat API
    participant RAG as RAG 引擎
    participant EMB as Embedding
    participant VS as 向量库
    participant KG as 知识图谱
    participant LLM as LLM

    U->>API: 发送问题
    API->>RAG: 触发检索
    RAG->>EMB: 向量化 query
    EMB-->>RAG: query vector
    RAG->>VS: 相似度检索 Top-K
    VS-->>RAG: 候选文档 chunks
    RAG->>KG: 图谱关联查询
    KG-->>RAG: 相关实体
    RAG->>RAG: 上下文融合 + 重排序
    RAG->>LLM: 注入 context + prompt
    LLM-->>API: 生成答案
    API->>U: 流式返回
    API->>API: 记录工单 + 效果事件
```

**关键技术**：
- **混合检索**: 向量检索（语义）+ 关键词检索（BM25） + 知识图谱（关系）
- **Re-Rank**: Cross-Encoder模型对Top-50候选重排序
- **Context Compression**: 长文档自动切片、提取关键句

### 3.3 多智能体 (Agent) 编排

品牌IP智能体采用 **ReAct + Function Calling** 架构，支持长期记忆与多步推理。

```mermaid
graph TB
    USER[用户输入] --> PERCEIVE[感知层<br/>理解意图]
    PERCEIVE --> PLAN[规划层<br/>任务分解]
    PLAN --> DECIDE{是否需要<br/>工具调用?}
    DECIDE -->|否| DIRECT[直接LLM生成]
    DECIDE -->|是| TOOL[选择工具]
    TOOL --> EXEC[执行工具]
    EXEC --> OBSERVE[观察结果]
    OBSERVE --> DECIDE
    DIRECT --> MEM[写入长期记忆]
    OBSERVE --> MEM
    MEM --> RESPOND[生成最终回复]
    RESPOND --> USER

    subgraph "工具库 (Tools)"
        T1[产品查询]
        T2[订单管理]
        T3[文化元素检索]
        T4[内容生成]
        T5[图片生成]
    end

    TOOL --> T1 & T2 & T3 & T4 & T5
```

### 3.4 文化元素知识图谱（隐式图）

不引入Neo4j等图数据库，复用PostgreSQL的CulturalElement表，通过**共享属性**定义隐式边。

```mermaid
graph LR
    A[烤全羊<br/>内蒙·传统工艺] ---|共享 region| B[手把肉<br/>内蒙·传统工艺]
    A ---|共享 type| C[蒙古袍<br/>新疆·传统工艺]
    B ---|共享 keyword 草原| D[那达慕<br/>内蒙·节庆民俗]
    C ---|共享 keyword 草原| D

    style A fill:#f9e,stroke:#333
    style B fill:#bbf,stroke:#333
    style C fill:#bfb,stroke:#333
    style D fill:#fbb,stroke:#333
```

**边定义**：
- 共享 `origin_region`（产地）
- 共享 `type`（类型）
- 共享至少1个 `keyword`（关键词）

**核心算法**：
| 算法 | 用途 | 复杂度 |
|------|------|--------|
| **BFS 路径查询** | find_path(source, target) | O(V+E) |
| **共同邻居推荐** | recommend_related(top_k) | O(V²) |
| **密度统计** | get_graph_stats() | O(V²) |

### 3.5 多平台内容自适应分发

采用**适配器模式 (Adapter Pattern)**，对4大主流平台（抖音/小红书/视频号/公众号）做内容适配。

```mermaid
graph TB
    ORIG[原始内容<br/>通用 PublishRequest] --> REG[PublisherRegistry]
    REG --> DOUYIN[DouyinPublisher<br/>字数≤1500<br/>需视频]
    REG --> XHS[XiaohongshuPublisher<br/>字数≤1000<br/>需图片]
    REG --> WECHAT[WechatPublisher<br/>字数≤20000<br/>无标签]
    REG --> WEIBO[WeiboPublisher<br/>字数≤2000<br/>可选图]

    DOUYIN --> ASYNC{asyncio.gather}
    XHS --> ASYNC
    WECHAT --> ASYNC
    WEIBO --> ASYNC

    ASYNC --> RESULT[PublishResult 聚合]
    RESULT --> DB[(PublishRecord 入库)]
    RESULT --> METRIC[效果事件埋点]
```

**关键设计**：
- **统一抽象**: `PublisherBase` 定义 `adapt() / publish() / validate()` 三个方法
- **Mock + Real 双模式**: 开发期 Mock、灰度期可切真实API
- **失败重试**: 5%随机失败可触发指数退避重试
- **异步并行**: `asyncio.gather` 4平台同步发布，延迟降低75%
