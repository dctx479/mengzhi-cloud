## 1. 用户业务流程测试

### TC-INT-USER-001: 新用户完整使用流程

**优先级**: P0
**测试时间**: 约15分钟

**业务流程**:
```
注册账号 → 登录系统 → 浏览产品 → 查看详情 → 使用AI对话 → 退出登录
```

**前置条件**: 无

**测试步骤**:

#### 步骤1: 用户注册
1. 访问注册页面 `/register`
2. 填写注册信息:
   - 用户名: `integration_user_001`
   - 邮箱: `int001@example.com`
   - 密码: `IntTest123!`
   - 用户类型: 个人
3. 获取验证码（模拟）
4. 提交注册

**步骤1验证**:
- 注册成功，返回201
- 数据库users表有新记录
- user_id不为空
- 密码已加密

#### 步骤2: 用户登录
1. 跳转到登录页面
2. 输入用户名和密码
3. 提交登录

**步骤2验证**:
- 登录成功，返回200
- 收到access_token和refresh_token
- Token保存到localStorage
- 跳转到首页

#### 步骤3: 浏览产品列表
1. 访问产品页面 `/products`
2. API自动加载产品列表

**步骤3验证**:
- 调用GET /api/v1/products
- Authorization Header包含token
- 返回产品列表
- 页面显示产品卡片

#### 步骤4: 搜索和筛选
1. 搜索关键词: "牛肉"
2. 筛选类别: "肉类"
3. 按价格升序排序

**步骤4验证**:
- 调用GET /api/v1/products?search=牛肉&category=肉类&sort_by=price&sort_order=asc
- 返回符合条件的产品
- 结果按价格排序

#### 步骤5: 查看产品详情
1. 点击第一个产品
2. 进入产品详情页 `/products/1`

**步骤5验证**:
- 调用GET /api/v1/products/1
- 调用GET /api/v1/products/1/cultural-info
- 显示完整产品信息
- 显示文化信息

#### 步骤6: 使用AI对话
1. 访问AI对话页面 `/chat`
2. 输入消息: "请介绍一下草原牛肉的特点"
3. 发送消息

**步骤6验证**:
- 调用POST /api/v1/chat/message
- conversation_id为null（新对话）
- 收到AI回复
- 对话保存到数据库
- conversations表有新记录
- messages表有2条记录（用户+AI）

#### 步骤7: 继续对话
1. 继续输入: "价格大概多少？"
2. 发送消息

**步骤7验证**:
- 调用POST /api/v1/chat/message
- conversation_id不为空（继续对话）
- AI回复考虑上下文
- messages表新增2条记录

#### 步骤8: 查看对话历史
1. 点击对话列表
2. 查看历史对话

**步骤8验证**:
- 调用GET /api/v1/chat/conversations
- 显示刚才的对话
- message_count正确

#### 步骤9: 退出登录
1. 点击退出登录
2. 确认退出

**步骤9验证**:
- 调用POST /api/v1/auth/logout
- localStorage清空
- 跳转到登录页
- 使用旧token访问API返回401

**整体验证**:
- 所有API调用成功
- 数据一致性:
  - 1个用户记录
  - 1个对话记录
  - 4条消息记录（2轮对话）
- 前后端数据同步
- 无JavaScript错误

### TC-INT-USER-002: Token过期自动刷新流程

**优先级**: P0
**测试时间**: 约5分钟

**业务流程**:
```
登录 → 等待Token过期 → 访问API → 自动刷新Token → 继续使用
```

**测试步骤**:

#### 步骤1: 用户登录
1. 登录系统
2. 记录access_token

#### 步骤2: 模拟Token过期
1. 修改系统时间（或等待30分钟）
2. 或直接使用过期的测试Token

#### 步骤3: 访问需要认证的API
1. 调用GET /api/v1/auth/me
2. 使用过期Token

#### 步骤4: 自动刷新
**预期行为**:
- 前端检测到401 + code: 20003
- 自动调用POST /api/v1/auth/refresh
- 使用refresh_token换取新token
- 更新localStorage
- 重新发起GET /api/v1/auth/me请求

#### 步骤5: 继续使用
1. 使用新token正常访问其他API

**验证**:
- 用户无感知刷新
- 不需要重新登录
- 新旧token不同
- 旧token加入黑名单

## 2. AI对话业务流程测试

### TC-INT-CHAT-001: AI对话完整流程（非流式）

**优先级**: P0
**测试时间**: 约10分钟

**业务流程**:
```
新建对话 → 发送消息 → 接收回复 → 查看历史 → 反馈评价 → 删除对话
```

**测试步骤**:

#### 步骤1: 新建对话
1. 用户已登录
2. 访问AI对话页面
3. 点击"新建对话"

**验证**:
- 聊天区域清空
- conversation_id为null

#### 步骤2: 发送第一条消息
1. 输入: "请介绍内蒙古特色农产品"
2. 点击发送
3. API调用: POST /api/v1/chat/message

**验证**:
- 请求参数:
  ```json
  {
    "content": "请介绍内蒙古特色农产品",
    "conversation_id": null,
    "agent_type": "assistant"
  }
  ```
- 响应包含:
  - conversation_id（新创建）
  - message对象（AI回复）
  - usage（Token消耗）
- 数据库验证:
  - conversations表新增1条
  - messages表新增2条（用户+AI）
  - conversation.message_count = 2
  - conversation.total_tokens > 0

#### 步骤3: 继续对话
1. 输入: "草原牛肉有什么特点？"
2. 发送消息

**验证**:
- 请求参数conversation_id不为空
- AI回复考虑上下文
- messages表新增2条
- conversation.message_count = 4

#### 步骤4: 查看对话历史
1. 刷新页面
2. 加载对话列表
3. 点击刚才的对话

**验证**:
- 调用GET /api/v1/chat/conversations
- 对话列表包含该对话
- 调用GET /api/v1/chat/conversations/{id}
- 显示所有4条消息
- 消息顺序正确

#### 步骤5: 消息反馈
1. 鼠标悬停在AI消息上
2. 点击"点赞"按钮

**验证**:
- 调用POST /api/v1/chat/feedback
- 请求参数:
  ```json
  {
    "message_id": 2,
    "rating": 5,
    "feedback_type": "helpful"
  }
  ```
- 数据库messages表更新反馈信息

#### 步骤6: 删除对话
1. 点击删除按钮
2. 确认删除

**验证**:
- 调用DELETE /api/v1/chat/conversations/{id}
- conversations表status变为"deleted"
- 对话列表不再显示

**测试时间**: 约15分钟

**业务流程**:
```
登录管理员 → 创建产品 → 更新产品 → 查看产品 → 删除产品
```

**测试步骤**:

#### 步骤1: 管理员登录
1. 使用管理员账号登录
2. role为"admin"

**验证**:
- 登录成功
- Token包含admin角色信息

#### 步骤2: 创建产品
1. 调用POST /api/v1/products
2. 提交完整产品数据

**验证**:
- 响应201
- 返回产品ID
- 数据库products表新增记录
- created_by为当前管理员ID

#### 步骤3: 更新产品
1. 调用PUT /api/v1/products/1
2. 更新价格和库存

**验证**:
- 响应200
- 数据库字段已更新
- updated_at时间戳更新
- updated_by为当前管理员ID

#### 步骤4: 普通用户查看
1. 切换到普通用户账号
2. 调用GET /api/v1/products/1

**验证**:
- 可以查看产品详情
- 看到更新后的价格和库存

#### 步骤5: 普通用户尝试删除
1. 调用DELETE /api/v1/products/1

**验证**:
- 返回403
- code: 20020
- 错误消息: "权限不足"
- 产品未被删除

#### 步骤6: 管理员删除
1. 切换回管理员
2. 调用DELETE /api/v1/products/1

**验证**:
- 响应200
- products表status变为"deleted"
- 产品列表不再显示

**数据一致性验证**:
- created_by = updated_by = 管理员ID
- 时间戳逻辑正确（created_at < updated_at）
- 软删除，记录仍存在
