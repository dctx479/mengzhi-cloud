### 3. 并发攻击防护 (2/2 通过)

#### 3.1 悲观锁机制

**测试用例**:
- ✅ `test_pessimistic_lock_on_order` - 订单查询使用悲观锁
- ✅ `test_concurrent_payment_creation` - 并发创建只生成一个支付

**验证内容**:
- 使用 `with_for_update()` 对订单加悲观锁
- 防止并发创建多个支付记录
- 检测到已有待支付记录时返回现有记录

**攻击场景**:
```
攻击者同时发送100个支付请求
→ 悲观锁确保只有一个请求能创建支付
→ 其他请求返回已存在的支付记录
→ 防止重复扣款
```

**安全等级**: 🔒 高
