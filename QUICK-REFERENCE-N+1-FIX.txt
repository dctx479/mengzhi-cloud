================================================================================
代码修改模式
================================================================================

模式 1: 一对多关系 (Conversation -> Messages)
--------
修复前:
  conv = self.db.query(Conversation).filter(...).first()
  messages = conv.messages  # 触发 N 次额外查询

修复后:
  conv = self.db.query(Conversation).options(
      joinedload(Conversation.messages)
  ).filter(...).first()
  messages = conv.messages  # 无额外查询

模式 2: 多对一关系 (Product -> Creator)
--------
修复前:
  product = self.db.query(Product).filter(...).first()
  creator = product.creator  # 触发 1 次额外查询

修复后:
  product = self.db.query(Product).options(
      joinedload(Product.creator)
  ).filter(...).first()
  creator = product.creator  # 无额外查询

模式 3: 多个关系预加载 (Order -> User, Package)
--------
修复前:
  order = self.db.query(Order).filter(...).first()
  user = order.user  # 1 次额外查询
  package = order.package  # 1 次额外查询

修复后:
  order = self.db.query(Order).options(
      joinedload(Order.user),
      joinedload(Order.package)
  ).filter(...).first()
  user = order.user  # 无额外查询
  package = order.package  # 无额外查询

性能对比
================================================================================

修复前的 SQL:
  SELECT * FROM products WHERE ... LIMIT 50;
  SELECT * FROM users WHERE id = ? (执行 50 次)

修复后的 SQL:
  SELECT * FROM products
  LEFT JOIN users ON ... 
  WHERE ... LIMIT 50;

Q: 修复后 API 返回值会变吗?

Q: 为什么 order_service 中的 joinedload 被注释了?
